# 常见问题

## 错误代码

### `#REF!`

**含义**：数据库文件不存在、表不存在、或列名错误。

**排查**：
1. 检查数据库路径是否正确（注意 Excel 中反斜杠需要写成 `\\`）
2. 使用 `=SqlTables("你的数据库路径")` 确认表是否存在
3. 使用 `=SqlSchema("你的数据库路径", "表名")` 确认列名

### `#NAME?`

**含义**：SQL 语法错误，或数据库连接失败。

**排查**：
1. 把 SQL 语句复制到 DB Browser for SQLite 等工具中验证
2. 检查路径中的特殊字符是否已转义
3. 确认数据库文件未被其他程序独占打开

### `#VALUE!`

**含义**：函数参数数量/类型不匹配，或查询执行过程中出错。

**排查**：
1. 检查必填参数是否遗漏（如 `SqlQuery` 需要 conn_str 和 sql 两个参数）
2. 检查 `SqlQueryP` 的参数数量是否与 SQL 中的 `?` 数量一致
3. 检查 `SqlCreateTable` 的数据区域是否为有效的二维数组

## 中文乱码

### 从 Excel 建表时中文列名乱码

确保 Excel 单元格中的中文是直接输入的，不是从某些软件复制过来的特殊编码字符。

### CSV 导入后中文显示为问号

`SqlImportCsv` 会自动尝试 UTF-8 解码，失败后会 fallback 到 GB18030（兼容 GBK）。如果仍乱码：
1. 用记事本打开 CSV，点击 **文件 → 另存为**，选择 "UTF-8" 编码后保存
2. 重新导入

## 性能问题

### 查询百万级数据时 Excel 卡死

使用 `SqlQueryL` 分页查询，而不是一次性 `SELECT *`：
```excel
=SqlQueryL(,"SELECT * FROM big_table", 1000, 0)
```

### 导入大 CSV 文件很慢

- 确保 CSV 没有大量空行或格式错误行
- CSV 解析器已使用事务批量插入，通常 10 万行在几秒内完成
- 如果超过 100 万行，考虑先用 `SqlImportCsv` 导入到文件数据库，再分页查询

## 连接与句柄

### 内存数据库的数据在什么时候丢失？

内存数据库（省略 conn_str 或使用 `conn_memory`）的数据在 **Excel 进程完全退出** 后丢失。如果只是关闭工作簿但 Excel 仍在运行，数据依然存在。

### 如何跨工作表共享内存数据库？

所有省略 conn_str 的函数默认连接到同一个共享内存数据库 URI：`file:sqlite_xll_shared?mode=memory&cache=shared`。因此 Sheet1 中创建的表，Sheet2 中可以直接查询。

### 句柄和路径有什么区别？

- **路径**：完整的数据库文件路径，如 `C:\\data\\test.db`
- **句柄**：`SqlConnect` 返回的字符串，如 `conn_1`、`conn_memory`

使用句柄的好处：
1. 公式更短，可读性更好
2. 连接被缓存，重复打开同一数据库时性能更高
3. 可以在公式中统一修改连接目标（改一处，全工作表生效）

## 其他

### 公式结果不随源数据更新而自动刷新

Excel 不会自动监控 SQLite 数据库文件的变化。如果外部程序修改了数据库，需要按 **F9** 手动刷新，或在 VBA 中调用 `Application.CalculateFull`。

### 如何查看 SQLite 支持的完整 PRAGMA 列表？

```excel
=SqlPragma(,"pragma_list")
```
